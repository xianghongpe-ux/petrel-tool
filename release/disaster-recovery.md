## 🔴 DR-01: 主 GitHub 被封

### 场景假设

GitHub 以 DMCA/制裁为由封禁 `petrel-ai` 组织及所有仓库。社区无法通过主仓库获取代码和发布包。

### 应对流程

#### 阶段 1: 确认 (0-2h)

- [ ] 确认封禁类型（只读/完全删除/组织封禁）
- [ ] 截图保留证据
- [ ] 通过 Telegram/Matrix 发布紧急公告
- [ ] 激活"镜像就绪"标记

#### 阶段 2: 激活镜像网络 (2-6h)

```
# 镜像源列表（按优先级排列）
1. GitLab:    gitlab.com/petrel-ai-mirror/dzn
2. Codeberg:  codeberg.org/petrel-ai/dzn
3. Gitee:     gitee.com/petrel-ai/dzn
4. 自建 Gitea: git.dzn.petrel-ai.org
5. 种子网络:  BitTorrent / IPFS / 协议种子 U 盘
```

- [ ] 验证镜像仓库完整性（`git fsck`）
- [ ] 同步所有分支和标签
- [ ] 触发 CI/CD 重新构建（镜像站）
- [ ] 更新 DNS TXT 记录，指示新仓库地址

#### 阶段 3: 社区迁移 (6-24h)

- [ ] 发布迁移指南（官网/社区频道/邮件列表）
- [ ] 更新所有文档中的仓库引用
- [ ] 启动 Codeberg/Gitee 作为主站点
- [ ] 分发协议种子 U 盘到核心节点

#### 阶段 4: 持续运营 (24h+)

- [ ] 建立多镜像自动同步
- [ ] 新增镜像源（持续增加）
- [ ] 评估法律应对方案

## 🟠 DR-02: 官网被 DDoS

### 场景假设

DZN 官网 `dzn.petrel-ai.org` 遭受持续 DDoS 攻击，导致所有服务（文档、看板、API）不可用超过 4 小时。

### 应对流程

#### 阶段 1: 确认与缓解 (0-1h)

- [ ] 确认攻击类型（L7 CC / L4 洪水 / DNS 放大）
- [ ] 切换 DNS 到 DDoS 防护（Cloudflare / 阿里云高防）
- [ ] 启用 CDN 缓存（所有静态资源 7 天 TTL）
- [ ] 核心 API 启用 IP 白名单

#### 阶段 2: 服务降级 (1-4h)

```
┌──────────────────────────────────────────────┐
│           正常模式 → 降级模式                  │
├──────────────────────────────────────────────┤
│ 看板        实时数据   → 本地缓存 + 手动刷新   │
│ 投票        在线投票   → 异步邮件投票          │
│ 市场        实时交易   → 离线订单簿            │
│ 网关        P2P 直连   → 中继节点 + 种子转发   │
│ 文档        CDN 加速   → IPFS 分布式文档       │
└──────────────────────────────────────────────┘
```

- [ ] 切换到降级模式
- [ ] 通过 Telegram/Matrix 通知社区
- [ ] 启用离线共识机制

#### 阶段 3: 核心运营保底 (4-24h)

- [ ] **黑启动方案**: 全部服务 offline，仅保留 P2P 节点网络
- [ ] **协议种子分发**: 紧急分发更新的种子 U 盘
- [ ] **共识暂停**: 暂停需要中央服务的共识验证，改用手动多签
- [ ] **数据同步**: 攻击恢复后，各节点通过 P2P 同步差异数据

#### 阶段 4: 恢复 (24h+)

- [ ] 攻击确认停止后，逐步恢复服务
- [ ] 有序恢复：网关 → 看板 → 市场 → 投票
- [ ] 数据一致性核查
- [ ] 更新安全策略

## 🟡 DR-03: 核心成员失联

### 场景假设

核心维护者（密钥持有人/GitHub Owner/DNS 管理员）因任何原因 72 小时以上无法联系。

### 应对流程

#### 阶段 1: 失联确认 (24h)

- [ ] 多渠道尝试联系（Telegram / Signal / Email / 电话）
- [ ] 联系备用联系人/家属
- [ ] 社区共识投票确认"失联状态"

#### 阶段 2: 权限接管 (24-48h)

```yaml
# 紧急权限转移矩阵
service:           primary_holder      backup_1              backup_2
GitHub Owner:      alice               bob                   community-vote
DNS Admin:         alice               bob                   charlie
Docker Hub:        bob                 charlie               alice
Code Signing Key:  multi-sig (3/5)     threshold signature   key ceremony
社区公告:         alice/bob           emergency-channel   广播
```

- [ ] 触发"死神协议"（Dead Man's Switch）
- [ ] 多签门槛从 2/3 降为 3/5（更多人可签名）
- [ ] 社区投票任命临时维护者
- [ ] 更换 DNS/CI/CD 等基础设施凭证

#### 阶段 3: 持续运营 (48-72h)

- [ ] 临时维护团队发布状态报告
- [ ] 社区投票决定是否需要选举正式维护者
- [ ] 持续尝试联系原维护者（未确认不剥夺权限）

#### 阶段 4: 恢复/移交 (72h+)

**场景 A**: 原维护者回归
- [ ] 安全检查：密钥轮换
- [ ] 权限逐步归还
- [ ] 事后复盘

**场景 B**: 确认失联
- [ ] 正式选举新维护者
- [ ] 全量密钥轮换
- [ ] 更新法律文件
